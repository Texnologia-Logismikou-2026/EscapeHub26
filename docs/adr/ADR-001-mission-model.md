# ADR-001: Data-Driven Μοντέλο Αποστολών σε JSON

- **Κατάσταση:** Εγκεκριμένο (Accepted)
- **Ημερομηνία:** 2026-11-23
- **Σχετικό Issue:** Issue #1 — Mission Model & Non-Linear Design

## Πλαίσιο (Context)
Στο Sprint 2 οι αποστολές πρέπει να υποστηρίζουν μη γραμμικές διαδρομές, πολλαπλούς τύπους γρίφων, κανόνες ξεκλειδώματος (`unlockRules`) και προσθήκη νέων αποστολών χωρίς αλλαγή του πηγαίου κώδικα. Παράλληλα, η βάση δεδομένων (`MissionSession`) αποθηκεύει ήδη δυναμικά `List<String> solvedPuzzles` και `List<String> unlockedEvidence`.

## Απόφαση (Decision)
Ο ορισμός κάθε αποστολής (διαδρομές, στοιχεία, γρίφοι, πηγές API, κανόνες ξεκλειδώματος, συνθήκη απόδρασης) αποθηκεύεται ως **αυτόνομο αρχείο JSON** στον φάκελο `src/main/resources/missions/*.json` και φορτώνεται κατά την εκκίνηση μέσω του `MissionDefinitionLoader` σε immutable Java Records (`MissionDefinition`).

Κάθε ορισμός φέρει και αριθμητικό `missionId` (για άμεση αντιστοίχιση με το `MissionSession.missionId` της PostgreSQL) και μοναδικό `code` (π.χ. `encrypted-library`).

## Εναλλακτικές που Απορρίφθηκαν
1. **Hardcoded λογική γρίφων σε Java classes:** Απαιτεί αλλαγή κώδικα και recompile για κάθε νέα αποστολή· παραβιάζει την απαίτηση επεκτασιμότητας.
2. **Πλήρης κανονικοποίηση σε 6+ πίνακες PostgreSQL (Paths, Puzzles, Rules κ.λπ.):** Αυξάνει σημαντικά την πολυπλοκότητα των migrations και των JPA queries στο Sprint 2 χωρίς άμεσο όφελος, εφόσον οι ορισμοί αποστολών είναι read-only templates.

## Συνέπειες (Consequences)
- **Θετικές:** Προσθήκη 2ης, 3ης κ.λπ. αποστολής απλώς με νέο `.json` αρχείο· εύκολο version control (Git diff) στον σχεδιασμό· άμεση επικύρωση δομής κατά την εκκίνηση και σε γρήγορα unit tests.
- **Αρνητικές:** Οι αλλαγές σε ορισμό αποστολής απαιτούν επανεκκίνηση της εφαρμογής (αποδεκτό για το τρέχον εύρος του project).
