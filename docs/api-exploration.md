# Διερεύνηση δημόσιων APIs — EscapeHub (Sprint 0)

> Στόχος: να εντοπιστούν τα δημόσια APIs που μπορούν να χρησιμοποιηθούν στους γρίφους, τα χρήσιμα endpoints,
> η μορφή των JSON αποκρίσεών τους, τα όρια χρήσης τους (rate limits) και ο τρόπος διαχείρισης σφαλμάτων.
> Παραδείγματα αποκρίσεων αποθηκευμένα στο `docs/exemples/` (μελλοντικά fixtures για τα tests).

## 1. Ανάγκες του παιχνιδιού

Ερωτήματα που το παιχνίδι πρέπει να μπορεί να θέτει στα APIs (ενδεικτική αποστολή «Villa Diodati»):

1. Από έναν τίτλο ή υπότιτλο (*The Modern Prometheus*), εύρεση του **συγγραφέα** και του **έτους πρώτης έκδοσης** ενός βιβλίου.
2. Από έναν συγγραφέα, εύρεση των **ημερομηνιών γέννησης και θανάτου** του.
3. Από ένα πρόσωπο, εύρεση των **οικογενειακών του σχέσεων** (πατέρας, μητέρα, σύζυγος).
4. Για έναν πραγματικό πίνακα/πορτρέτο, εύρεση του **ζωγράφου** και της **ημερομηνίας δημιουργίας** του.
5. **Υποχρεωτική συσχέτιση (MVP §6)**: μεταφορά ενός αποτελέσματος από το Open Library (τον συγγραφέα) στο Wikidata (την οικογένειά του).

## 2. Open Library

- Τεκμηρίωση: https://openlibrary.org/developers/api — Search: https://openlibrary.org/dev/docs/api/search
- Δεν απαιτείται κλειδί API, αποκρίσεις σε JSON.

### Endpoints που επιλέχθηκαν

| Endpoint | Ρόλος | Χρήσιμα πεδία |
|---|---|---|
| `GET /search.json?q=<κείμενο>&limit=1&fields=key,title,author_name,author_key,first_publish_year` | Εύρεση έργου από κείμενο | `docs[].title`, `docs[].author_name[]`, `docs[].author_key[]`, `docs[].first_publish_year`, `docs[].key` |
| `GET /authors/<ID>.json` (π.χ. `OL25342A`) | Καρτέλα συγγραφέα | `name`, `birth_date`, `death_date`, `remote_ids.wikidata` |
| `GET /works/<ID>.json` (π.χ. `OL450063W`) | Καρτέλα έργου | τίτλος, συγγραφείς, θέματα |

Αναγνωριστικά: κατάληξη `W` = έργο (work), `M` = έκδοση (edition), `A` = συγγραφέας (author).

### Παρατηρήσεις

- Αποτέλεσμα δοκιμής: *The Modern Prometheus* → *Frankenstein; or, The Modern Prometheus*, Mary Shelley (`OL25342A`), 1818, έργο `/works/OL450063W`.
- Η αναζήτηση επιστρέφει **πολλά αποτελέσματα** (`numFound: 471`): το πρώτο δεν είναι εγγυημένα σταθερό → χρειάζονται fixtures.
- Η πλήρης απόκριση είναι πολύ μεγάλη (το πεδίο `ia` έχει ~100 γραμμές) → χρησιμοποιούμε πάντα `fields=`.
- Το `author_name` είναι **πίνακας** (ένα βιβλίο μπορεί να έχει πολλούς συγγραφείς).
- Τα `birth_date` / `death_date` είναι **ελεύθερο κείμενο** (`"30 August 1797"`) → δεν πρέπει να χρησιμοποιούνται για την επικύρωση απαντήσεων.
- Οι καρτέλες τροποποιούνται (`revision: 47`, `last_modified: 2026-08-11`) → τα δεδομένα αλλάζουν με τον χρόνο.
- **Γέφυρα προς το Wikidata**: `remote_ids.wikidata` = `"Q47152"` για τη Mary Shelley.

### Rate limits και κανόνες χρήσης

- Χωρίς ταυτοποίηση: **1 αίτημα/δευτερόλεπτο**· με `User-Agent` + email: **3 αιτήματα/δευτερόλεπτο**.
- Ζητείται: ταυτοποίηση της εφαρμογής, caching, όχι scraping σελίδων HTML, όχι μαζική λήψη δεδομένων.
- Πηγή: https://openlibrary.org/developers/api

## 3. Wikidata

- Πρόσβαση στα δεδομένα: https://www.wikidata.org/wiki/Wikidata:Data_access
- Δεν απαιτείται κλειδί API, αποκρίσεις σε JSON. **Το User-Agent είναι υποχρεωτικό.**

### Endpoints που επιλέχθηκαν

| Endpoint | Ρόλος |
|---|---|
| `GET https://www.wikidata.org/wiki/Special:EntityData/<QID>.json` | Πλήρης καρτέλα μιας οντότητας (π.χ. `Q47152`) |
| `GET https://www.wikidata.org/w/api.php?action=wbsearchentities&search=<όνομα>&language=en&format=json` | Αναζήτηση οντότητας με το όνομά της → λήψη του QID |
| `GET https://query.wikidata.org/sparql?query=<SPARQL>&format=json` | Στοχευμένα ερωτήματα (π.χ. «γονείς του Q47152») |

### Μορφή απόκρισης (EntityData)

- Διαδρομή: `entities.<QID>.labels.<γλώσσα>.value` για το όνομα· `entities.<QID>.claims.<Pxx>` για τις ιδιότητες.
- Οι τιμές των σχέσεων είναι **αναγνωριστικά** (`Q...`) και όχι ονόματα → χρειάζεται δεύτερη κλήση (ή SPARQL με labels).
- Χρήσιμες ιδιότητες: `P22` πατέρας, `P25` μητέρα, `P26` σύζυγος, `P569` γέννηση, `P570` θάνατος, `P50` συγγραφέας, `P170` δημιουργός (έργο τέχνης), `P571` ημερομηνία δημιουργίας.
- Οι ημερομηνίες είναι **δομημένες** (μορφή ISO, π.χ. `+1797-08-30T00:00:00Z`) → αξιόπιστες για την επικύρωση απαντήσεων.
- Η απόκριση του EntityData είναι **πολύ μεγάλη** → εξάγουμε μόνο τα απαραίτητα πεδία.

### Rate limits και κανόνες χρήσης

- Πολιτική User-Agent της Wikimedia: όνομα εφαρμογής + στοιχεία επικοινωνίας (email ή URL). Χωρίς έγκυρο User-Agent: σφάλμα 403 ή χαμηλότερα όρια.
  Πηγή: https://foundation.wikimedia.org/wiki/Policy:Wikimedia_Foundation_User-Agent_Policy
- Γενικά όρια για όλα τα APIs της Wikimedia από το 2026 (χαμηλότερα για μη ταυτοποιημένα αιτήματα· υπέρβαση → **HTTP 429**).
  Πηγή: https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits
- Υπηρεσία SPARQL: μέγιστος χρόνος **60 δευτερόλεπτα** ανά ερώτημα· ανά client (User-Agent + IP) **60 δευτερόλεπτα επεξεργασίας ανά λεπτό** και **30 ερωτήματα με σφάλμα ανά λεπτό**· σε περίπτωση 429, τηρούμε την κεφαλίδα `Retry-After`.
  Πηγή: https://www.mediawiki.org/wiki/Wikidata_Query_Service/User_Manual#Query_limits

## 4. Συσχέτιση των δύο πηγών (MVP §6)

```
"The Modern Prometheus"
  └─ Open Library /search.json      → συγγραφέας OL25342A, 1818
       └─ Open Library /authors/OL25342A.json → remote_ids.wikidata = Q47152
            └─ Wikidata EntityData Q47152     → P22 (πατέρας), P25 (μητέρα), P26 (σύζυγος)
```

## 5. Διαχείριση σφαλμάτων

| Περίπτωση | Αναμενόμενη συμπεριφορά της εφαρμογής |
|---|---|
| Timeout / το API δεν είναι προσβάσιμο | Χρήση του αποθηκευμένου snapshot, σαφές μήνυμα στον παίκτη |
| 404 (ανύπαρκτο αναγνωριστικό) | Αντιμετώπιση ως «κανένα αποτέλεσμα» |
| 0 αποτελέσματα (`numFound: 0`, κενός πίνακας) | Μήνυμα «κανένα αποτέλεσμα», χωρίς exception |
| 429 Too Many Requests | Διακοπή κλήσεων, τήρηση του `Retry-After` |
| Πεδίο που λείπει / απρόσμενη μορφή | Επικύρωση της απόκρισης· ο γρίφος δεν πρέπει ποτέ να «κρασάρει» |

## 6. Προτάσεις για την ομάδα

- Κοινό **User-Agent**: `EscapeHub/<version> (<email επικοινωνίας της ομάδας>)`.
- **Timeout** στον client: 5 δευτερόλεπτα (Open Library, EntityData)· SPARQL: έως 10 δευτερόλεπτα, με απλά ερωτήματα και `LIMIT`.
- **Περιορισμός συχνότητας** στην εφαρμογή: ≤ 1 αίτημα/δευτερόλεπτο ανά πηγή.
- **Cache + snapshots**: αποθήκευση των αποκρίσεων που χρησιμοποιεί η αποστολή· οι σωστές απαντήσεις επικυρώνονται με βάση τα snapshots και όχι τα ζωντανά δεδομένα (MVP §7).
- **Tests**: το CI χρησιμοποιεί τα αρχεία του `docs/exemples/` ως fixtures (mocks/stubs), χωρίς πραγματικές κλήσεις δικτύου.
- Κατανομή: Open Library για τους γρίφους «βιβλίο», Wikidata για τους γρίφους «πρόσωπο / οικογένεια / έργο τέχνης».
